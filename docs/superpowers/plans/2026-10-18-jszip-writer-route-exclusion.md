# JSZip Writer-route Exclusion Implementation Plan

> **For agentic workers:** Follow the current environment's sequential plan execution workflow. Tower assigns implementation and fresh-context reviewers; this author does not launch agents. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove JSZip archive-generation/STORE/DEFLATE writer capability from both production closures while preserving the real offline reader and correcting its false-positive ownership guard.

**Architecture:** Use source-bound, narrowly scoped build-time pruning of proven writer-only members, not filename exemptions or runtime disabling. Retain shared reader modules with explicit decode-only provenance. Every production build must compare its actual bytes against a separate, reviewed manifest-only reference compilation before publication; provenance records and a later test rebuild alone are insufficient.

**Tech Stack:** Existing TypeScript, Node `node:test`, esbuild browser CJS/ES2018, JSZip 3.10.1, docx-preview 0.3.7 and pako inflate; no new dependency or version/API change.

**Spec:** `docs/superpowers/specs/2026-10-18-jszip-writer-route-exclusion-design.md`; parent `docs/superpowers/specs/2026-10-11-office-document-fidelity-design.md` and `docs/superpowers/plans/2026-10-11-office-document-fidelity.md` (W75/W95/W139 remain governing).

## Review Focus

1. STORE generation can survive without pako Deflate: remove and probe STORE `compressWorker` and compressed-byte reuse (Tasks 1–3).
2. Mutable `_pakoAction` can revive a dispatcher even with one normal Inflate caller: replace dynamic constructor dispatch with an unconditional Inflate constructor (Tasks 1–3).
3. CRC corruption can appear accepted because product CRC checks are disabled: separately test the actual check-enabled loader seam without changing policy (Task 3).
4. Internal multi-argument `file` registration is necessary for reads: retain it and verify entry construction, rather than treating every setter as export (Task 3).
5. Node-worker parse success is not render/app isolation proof: preserve descriptor/termination tests, add render-result orchestration coverage and explicitly label mocked render versus real parse (Task 4).
