# Docs Reorganization Implementation Plan

> **For agentic workers:** Use the installed `swarm-cluster` skill for approved parallel work, or follow the current environment's in-session plan execution workflow. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move long-form project documentation out of the repository root and shorten both README files to the requested core sections without breaking release tooling or docs links.

**Architecture:** Keep standard community entry files in the root (`README.md`, `README.zh-CN.md`, `CHANGELOG.md`, `LICENSE`, `AGENTS.md`), move five long-form Markdown references under `docs/`, and extract detailed usage/performance/release material from both READMEs into linked docs pages.

**Tech Stack:** Markdown, Node.js release scripts, npm quality gates.

**Spec:** User request in this session — "项目根目录里的文档太多了吧，整理到 docs 里去。其次 README 的内容是不是太多了，保留主要的 feature 展示、使用相关注意、开发相关注意、上游协议等说明就好了，其他的按 markdown 文件塞 docs 里不好吗，整这么长"

## Global Constraints

- Preserve the untracked design file `docs/superpowers/specs/2026-10-23-virtualization-isolation-helper-design.md` unchanged.
- Do not stage or commit anything.
- Keep local-only, read-only product behavior and repository release rules unchanged.
- Keep English and Chinese README content aligned in scope.
- Keep release tooling able to find `THIRD_PARTY_LICENSES.md`, `COMMUNITY_PLUGIN_CHECKLIST.md`, and `XLSM_COMPATIBILITY.md` after the move.
- Avoid introducing stale root-path Markdown links.

## Review Focus

- Release scripts may still point at old root paths after the move; update them and run the release-check path.
- README links must continue to resolve from the repository root, while links between files moved into `docs/` must use correct relative paths.
- Removing README sections can accidentally drop install/upgrade warnings, development gate commands, or upstream/license attribution; those must survive in docs pages linked from README.
